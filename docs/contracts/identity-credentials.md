## 0. 范围

本契约固化 Q6：账号口令存储、员工访问凭据形态与哈希、凭据生命周期四状态在 Web 会话与 Git HTTP 两类入口的生效语义、Web 会话机制、密钥清单与轮换、初始管理员初始化与账号恢复、审计主体关联。

不在本契约内：库角色模型与分支规则（架构 §4.2/§4.3，T5 细化）；审计记录 schema（T5）；错误协议格式（T2 validation 契约）；SSO（第二阶段，架构 §1.3）。

## 1. 身份模型与凭据归属

认证主体（subject）= 员工账号。所有凭据与会话都归属且仅归属一个员工账号【依据：架构 §4.1「Agent 使用员工身份……这些凭据都归属员工」】。凭据只有两类：

| 凭据类 | 载体 | 使用入口 | 生命周期 |
|---|---|---|---|
| Web 会话 | 不透明 session ID + Cookie | 网页（Web UI/API 同源调用） | §4 |
| 员工访问凭据（token） | 不透明随机 token | Git HTTPS（Smart HTTP）、CLI/API | §3，可过期、可撤销 |

同一员工可持有多条访问凭据（例如本地 Harness 与托管 Harness 各一条），凭据之间互不连带：撤销一条不影响其他条与 Web 会话；注销会话不撤销 token。Agent 不存在独立身份，一律以所用凭据归属的员工计【依据：架构 §4.1】。托管 Harness 必须按员工隔离凭据与工作目录【依据：架构 §4.1、§7.2】。

## 2. 账号与口令

- 账号由实例管理员邀请创建（第一版本地账号，无自助注册）【依据：架构 §4.1】。username 显式格式校验（S37 补记）：裸名 `^[a-z0-9][a-z0-9._-]{0,62}$` 或带域名 `^[a-z0-9][a-z0-9._-]{0,20}@[a-z0-9][a-z0-9-]{0,39}$`（dshent 平台委托映射 `m<id>@<workspace-slug>` 形态；存量裸名不受影响）；非法 → 400 E-RES-004。校验单源于 `server/src/identity/username.ts`，邀请创建与 bootstrap 共用。
- 口令策略：最小长度 12（可配上限至 64），不强制组合规则、不强制周期更换【依据：NIST SP 800-63B 5.1.1（长度优先、拒绝组合规则与周期更换）】；泄露口令筛查（比对已泄露口令集）为可选能力且默认关闭——企业内网部署不假设可外联，待部署规格确认。
- 口令存储：**Argon2id**，参数 m=19456 KiB（19 MiB）、t=2、p=1【依据：OWASP Password Storage Cheat Sheet——Argon2id 为首选算法，所列参数为其最低推荐配置（2026-10-12 在线核对原文）】。盐随机内嵌于哈希串（modular 格式）。Node/TS 实现可选原生绑定（`argon2` / `@node-rs/argon2`）或纯 WASM（`hash-wasm`），库选型待 T1，参数与本契约为准。
  - 被拒备选：bcrypt（可用但内存硬度弱于 Argon2id，OWASP 列为次选）；PBKDF2（GPU 攻击成本更低）；明文或可逆加密（不可接受）。
- 登录防暴力破解：按「账号 + 来源 IP」指数退避（连续失败后延迟递增，窗口封顶），失败提示统一为「用户名或口令错误」；不做无管理动作的永久锁定（防账号拒绝服务）。阈值可配，默认值 S2 实现定。
- 口令重置后：该账号全部 Web 会话失效；访问凭据不自动撤销（停用/撤销是独立管理动作），管理界面提示一并处理。

## 3. 员工访问凭据（token）

### 3.1 形态与传输

- 形态：`ngt_` 前缀 + 32 字节 CSPRNG 随机值的 base64url（共 43 字符随机部）。前缀用于密钥扫描工具识别【业界同模式参考：GitHub PAT（ghp_）、GitLab PAT（glpat-）】。
- 明文只在创建响应中返回一次；服务端与 Web UI 此后仅显示前缀与末 4 位（识别用）。凭据不写入 remote URL、仓库内文件或日志【依据：架构 §8.1】。
- 传输：Git 走 HTTP Basic（Smart HTTP 惯例），CLI/API 走 `Authorization: Bearer`；仅经 HTTPS【依据：架构 §3.2 第一版 HTTPS-only】。

### 3.2 存储与哈希（决策）

服务端存储 `HMAC-SHA256(pepper, token)`，不存明文、不存可逆值【依据：架构 §8.1「服务端对凭据保存不可逆校验值」；OWASP——API 令牌应按凭据对待，以服务端密钥做 HMAC 后存储】。pepper 为 32 字节随机文件，位于 `/data/keys/token-pepper.key`（权限 0600）。这使架构 §10「凭据相关密钥必须另有安全备份」有具体所指。

- 被拒备选：明文/可逆存储（任何读取即冒用）；裸 `SHA-256(token)`（32 字节高熵 token 下抗原像成立，但数据库单独泄露时持有候选值者可离线验证；且 §10 密钥条款落空）。
- 查找方式：以 HMAC 输出为唯一索引键查表；token 明文从不作为索引或日志字段。
- 存储串内嵌 pepper 版本（形如 `hmacv1$<hex>`），支撑 §6.2 轮换。

### 3.3 存储字段（语义；列名定稿待 T5）

| 字段 | 语义 |
|---|---|
| id / employee_id | 凭据 ID / 归属员工（外键；归属关系不可变更） |
| name | 展示名（员工自起，如「本地 Harness」） |
| token_hash | §3.2 校验值（含 pepper 版本） |
| scope | §3.4 范围收窄声明 |
| created_at / expires_at / revoked_at | 创建 / 到期（必填，≤ 实例上限，默认上限 90 天可配）/ 撤销时间（NULL=未撤销） |
| last_used_at | 观测字段；更新节流（≥60 秒间隔批量写），不参与任何授权判断 |

### 3.4 范围：只能收窄

scope 声明两维：`access ∈ {read, read_write}`；`vaults` 为库允许清单（空 = 全部有权库）。每次使用时与员工当前权限**取交集**后判定：凭据永远不能访问员工无权的库，也不能以高于员工角色的权限写入【依据：架构 §4.1「凭据范围只能收窄员工权限，不能扩大权限」】。员工权限被收窄时，凭据可用范围随之自动收窄，无需逐凭据改配。

### 3.5 创建、查看与撤销

- 员工自助创建与管理员代管并存；Web 提供「查看访问凭据」页【依据：架构 §6 能力清单】。每员工上限默认 20 条（可配）。
- 创建时必选到期日（≤ 实例上限），无自动续期；到期或撤销后的 token 不可复活，只能新建。
- 撤销为即时操作，生效语义见 §5。

## 4. Web 会话

- 机制：**服务端会话表 + 不透明 session ID**（32 字节随机，base64url）。Cookie 属性：`HttpOnly; Secure; SameSite=Lax`（Secure 默认开；纯 HTTP 本地/内网试用形态可经 `NOTEGIT_COOKIE_SECURE=0` 显式关闭——该形态同链路可克隆会话、口令明文，禁生产，E9 D54），会话固定防护为登录成功后重发新 ID。ID 在会话表同样以 `HMAC-SHA256(pepper, sid)` 形式存储，键管理与 §3.2 同源。
  - 被拒备选：JWT/签名 Cookie 等无状态方案——账号停用与会话吊销必须对下一请求生效（§5、DOD-03），无状态令牌需维护实时拒绝名单，复杂且易错，违背 §4.1 即时撤销语义。
- 过期：`idle_timeout` 默认 7 天（滑动续期）、`absolute_timeout` 默认 30 天，均管理员可配；过期判定以服务端存储的时间戳为准，逐请求比较。
- CSRF：SameSite=Lax 之上，所有写操作校验同源请求头；具体机制随 T5 API 契约定稿。
- 会话与 token 相互独立（§1）：本文件两处生命周期互不联动，管理动作（停用、重置口令）除外（§5）。

## 5. 生命周期四状态 → 请求后果表

### 5.1 检查点模型（生效延迟边界的依据）

所有请求在服务端经两层检查，**全部实时查库，无权限缓存**：

1. **认证层**（Web 与 Git/API 每请求）：token/会话存在、未撤销、未过期，且归属账号 `active`。索引查表，无缓存。
2. **授权层**（涉及库的每请求，读路径与写路径一致）：实时查库成员关系与角色。
   - 依据：DOD-03「凭据到期、撤销、账号停用或成员撤权阻断后续请求」、S2 完成标准「撤权与停用对后续请求生效」；单实例 DB 索引查表成本可接受（架构 §9 初版单实例）。
   - **任何形式的权限缓存/TTL（含读路径）不在本契约允许范围**；未来如基准测试证明需要缓存，必须先经 epic ADR + DoD 修订提案由 master 归档后方可引入（协调人 2026-10-12 批复）。
3. **写路径附加**：执行点（Git pre-receive / 网页发布组件 update-ref 前）实时复查权限与分支规则【依据：架构 §5.4「权限变更和写入的执行需在服务端协调，避免检查后权限失效仍继续发布」】。

### 5.2 四状态后果表

| 状态 | 触发条件 | Web 会话入口 | Git HTTP / API（token）入口 | 生效点与延迟边界 |
|---|---|---|---|---|
| 凭据过期 | `expires_at ≤ now` | 无影响（会话是独立凭据，自身过期见 §4） | 401，提示「凭据已过期」；不可续期，须新建凭据 | 认证层逐请求比较 `expires_at`：**下一请求立即生效，零延迟** |
| 凭据撤销 | `revoked_at` 置位（员工或管理员） | 无影响（除非同时执行账号停用） | 401；审计事件与过期区分（revoked） | 认证层实时查表：**下一请求立即生效，零延迟** |
| 账号停用 | `employee.active = false` | 该账号**全部会话即刻视为无效**：下一请求被登出（页面跳登录 / API 401），无宽限期 | 该账号**全部 token** 401，无论各 token 自身状态 | 认证层逐请求检查账号 active：**下一请求立即生效，零延迟** |
| 库成员撤权 | 该员工在该库的成员关系被移除 | 该库从列表与搜索结果消失（下一次渲染即实时查权限）；直接访问该库路径 → **404** | 对该库的 refs 发现、对象读写、push 一律 **404**（clone/fetch/push 均拒绝）；其他库不受影响 | 授权层实时查表（读写一致）：**下一请求立即生效，零延迟**；在途 push 在执行点复查时被拒并记审计（拒绝） |

- 撤权返回 404 而非 403：对无权者与不存在者响应一致，不泄露库存在性【依据：架构 §4.2「未授权的库不进入列表和搜索结果」的同源原则；业界同模式：GitHub 对无权仓库返回 404】。被拒备选：403（向未授权者确认了库存在）。

### 5.3 边界条款

- **在途操作**：按其认证与授权通过时刻放行完成。「后续请求」指该操作完成后的新请求【依据：架构 §4.2「权限更改对后续服务端请求生效」的语义边界】。中断已在途的长传输代价高且难以一致实现，被拒备选。
- **已下载副本无法收回**：撤权与停用只约束后续服务端请求【依据：架构 §4.2、§12 边界表「已下载内容不能收回」】。
- **时钟权威**：过期判定只使用服务端时钟；客户端时钟不参与任何判定。
- **单实例假设**：上述「实时查库 = 立即生效」依赖单实例单进程（或进程间共享同一存储且无副本缓存）。多实例一致性不在第一版范围【依据：架构 §9】。

## 6. 密钥清单与轮换

> 本表是实例全部机密的权威清单；[backup-recovery.md](backup-recovery.md) 的密钥备份集引用本表，不得另行增删。

### 6.1 密钥清单

| # | 密钥/机密 | 生成 | 存储位置 | 权限 | 用途 | 轮换 |
|---|---|---|---|---|---|---|
| K1 | token/session HMAC pepper（32B） | 首次初始化自动生成 | `/data/keys/token-pepper.key`（持久卷） | 0600，仅应用进程 | 访问凭据与会话 ID 的 HMAC 键 | §6.2，在线操作 |
| K2 | Argon2id 盐 | 每口令随机 | 内嵌于 DB 口令哈希串 | 随数据库 | 口令哈希 | 无独立轮换，随口令重置自然更换 |
| K3 | TLS 服务端私钥/证书 | 部署方提供 | 部署层（反向代理或应用终止 TLS，形态待 T1/部署规格） | 部署方管控 | HTTPS 接入 | 常规证书运维（企业 PKI/ACME），实例外流程 |
| K4 | 数据库连接口令 | 部署方/初始化生成 | 环境变量或 `/data/config` 配置（不进 Git、不进日志） | 0600 | 应用连接管理数据库 | 管理员流程：数据库侧与配置侧同步更换 |
| K5 | 一次性引导/恢复令牌 | 初始化或恢复时生成 | 明文仅显示一次；库内只存哈希 + 过期 + 单次计数 | — | §7 初始管理员与账号恢复 | 单次使用即失效，天然轮换 |
| K6 | （预留）签名密钥 | — | 当前设计不采用无状态签名方案（§4），如 T1 推翻该决策须回本契约补行 | — | — | — |

### 6.2 pepper 轮换（版本化列表；协调人 2026-10-12 批复）

pepper 文件维护版本化列表：`active`（新 HMAC 计算用）+ `retired[]`（**仅校验用**，各带退役日期）。哈希串内嵌 pepper 版本（§3.2），校验按版本选键。

轮换步骤（在线操作，不需要维护模式）：

1. 生成新 pepper 置为 active，原 pepper 移入 retired，记审计事件。
2. 迁移期：既有 token/会话校验命中 retired 键时，验证成功后立即以 active 键**重算并回写**（rehash-on-use），对用户透明。
3. 迁移完成：retired 条目超过宽限期（默认 30 天，可配）即从文件移除并安全擦除；宽限期内从未被使用而未迁移的凭据与会话全部失效——员工重新登录、重新签发访问凭据（提前公告）。移除记审计事件。
4. 备份联动：迁移窗口内产生的备份必须包含完整 pepper 文件（含 retired 条目），否则恢复后旧哈希无法校验——见 backup-recovery.md §6。

- 触发时机：疑似泄露、定期（建议每年）、经手人员变动等，由管理员发起。
- 取舍边界：宽限期内 retired pepper 若泄露仍可校验旧哈希；以有界宽限期换取既有凭据可用性。被拒备选：轮换即全量失效（所有员工与 Agent 同时中断，可用性代价高）。

## 7. 初始管理员初始化与账号恢复（防锁死）

### 7.1 初始管理员初始化

1. 首次启动检测到用户表为空 → 进入**初始化态**：Web/API/Git 一切业务入口不可用，仅保留初始化端点。
2. 应用将一次性 bootstrap token（K5，32B 随机）写入 `/data/config/admin-bootstrap.token`（0600）；管理员在主机读取（如 `docker exec` 后 cat）。
   - 被拒备选：打印到容器 stdout——日志采集系统可能长期留存机密，违背「凭据不进日志」（架构 §8.1 同源原则）。
3. 管理员在初始化页/CLI 提交 token + 自定用户名口令 → 创建实例管理员账号 → token 单次失效，文件由应用删除，初始化态退出。
4. 用户表非空时初始化端点永久不可用；bootstrap token 重放无效。

依据：F01「首次管理员初始化」、DOD-01「按文档启动并完成管理员初始化」；业界同模式参考：Gitea/Forgejo 安装向导、GitLab 初始 root 口令。

### 7.2 账号恢复

- **普通员工**：实例管理员在管理页发起口令重置 → 生成一次性恢复令牌（K5：库内哈希 + 短时效 + 单次）→ 经企业内渠道（线下/IM）交付。第一版不假设 SMTP 可用，邮件投递为可选部署能力（待部署规格）。重置完成后该账号会话全部失效（§2）。
- **实例管理员口令丢失、仍有其他在岗管理员**：任一管理员按普通员工流程重置。
- **管理员全员锁死**（最后防线）：主机侧恢复——在部署主机执行容器 CLI（如 `docker exec <container> notegit admin recover`，命令名待 T1）生成一次性恢复令牌（K5，短时效），管理员据此重设口令。
  - 合理性边界：能访问部署主机/数据卷者本已等同完全控制实例（可直接读卷、改库）；主机侧恢复不扩大攻击面，仅将既有宿主权限显式化为**可审计动作**（产生审计事件，记录来源为主机侧）。
  - 被拒备选：邮件自助重置（依赖 SMTP，第一版不可假设）；无恢复机制（首次部署误锁死后无法自救，违背 F01）。

## 8. 审计主体关联

- 每条审计记录的主体字段：`employee_id`（**认证主体**）+ 凭据载体标识（credential_id / session 短哈希）+ 入口（web / api / git）。字段定稿待 T5。
- **commit 的 author/committer 由客户端可填，仅作内容元数据展示，不进入主体字段、不用于任何权限判断**【依据：架构 §4.4「以服务端认证身份记录实际推送者……commit author/committer 不能单独作为身份凭证」；DOD-03 同款】。
- Agent 可选 commit trailer（工具、任务来源）作为线索记录，不作可信身份判断【依据：架构 §4.4】。
- 凭据域审计事件：凭据创建/撤销、pepper 轮换与 retired 移除、主机侧恢复、账号停用/启用、口令重置。认证失败不逐条入审计（防噪音与日志填充），以失败计数指标呈现（细化待 T5）。
- 审计记录属权威管理数据，纳入一致备份【依据：架构 §3.1、§4.4；流程见 backup-recovery.md】。

## 10. 决策汇总

| id | 决策 | 依据 | 被拒备选 |
|---|---|---|---|
| D-IC-01 | 访问凭据为不透明随机 token，`ngt_` 前缀，明文仅示一次 | 架构 §4.1、§8.1；业界前缀惯例 | JWT 类自包含令牌（即时撤销需拒绝名单） |
| D-IC-02 | 口令 Argon2id（m=19MiB, t=2, p=1），长度策略遵 NIST 800-63B | OWASP、NIST SP 800-63B 5.1.1 | bcrypt、PBKDF2、明文/可逆 |
| D-IC-03 | token/会话 ID 存 `HMAC-SHA256(pepper, ·)`，pepper 32B 文件 0600 | 架构 §8.1、§10；OWASP | 裸 SHA-256、可逆存储 |
| D-IC-04 | Web 会话 = DB 会话表 + 不透明 ID + HttpOnly Cookie | 架构 §4.1 即时撤销、DOD-03 | JWT/签名 Cookie |
| D-IC-05 | 认证与授权检查每请求实时查库，读写路径一致，无权限缓存 | DOD-03、S2 完成标准、协调人 2026-10-12 批复 | 读路径 ≤60s 缓存（被否决：静默放宽 DoD） |
| D-IC-06 | 撤权/无权库统一返回 404 | 架构 §4.2 反存在性泄露 | 403（泄露存在性） |
| D-IC-07 | bootstrap token 写数据卷文件，不用 stdout | §8.1 凭据不入日志的同源原则 | stdout 打印（日志采集留存机密） |
| D-IC-08 | 管理员锁死以主机侧一次性恢复令牌兜底 | 宿主访问权=完全控制前提；Gitea/GitLab 同模式 | 邮件自助重置（不假设 SMTP）；无兜底（锁死不可恢复） |
