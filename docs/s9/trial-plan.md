# E1 企业试用计划——天穹智能（DOD-14）

2026-10-16 物化。触发：仓库所有者指定试用团队「天穹智能」（DOD-14 缺口解锁条件链
第 1 步——[e1-closure-check §3](e1-closure-check.md)）。本计划是 S9-T3 的交付面：
角色覆盖、环境清单、真实知识集、执行步进与反馈处置。**本计划不构成试用证据**——
DOD-14 关闭以 T4（三角色 × 两 Harness 全走通 + 反馈处置）的真实执行记录为准。

## 1. 试用方与角色覆盖

| 角色 | 覆盖面 | 落实状态 |
|---|---|---|
| 管理员 | 建库/成员与角色管理/邀请/凭据管理面/维护模式/审计查询 | 待天穹智能指定人选 |
| 知识贡献者 | 网页编辑/草稿/上传/重命名删除/git push 双入口 | 待天穹智能指定人选（≥1） |
| Agent | CLI（notegit login/setup/lint/sync）+ §9 读端点（vaults/tree/docs/审计查询）+ 凭据委托 | 待天穹智能提供执行环境 |

试用方负责各角色的真人/真实执行体；master 不代演、不虚构人选（DOD-14 口径）。

## 2. 两种 Harness 环境（epic 风险行 6 口径：隔离实测，纯文档不可替代）

| 环境 | 形态 | 状态 |
|---|---|---|
| 本地 | 单容器 compose（deploy/README 步进；构建期断言+初始化演练 16 步链） | 待建（试用启动时按手册新建，不复用 demo 数据） |
| 托管 | 经天穹智能认可的隔离部署环境（形态待其确认：其内网主机/云主机均可） | 待天穹智能确认 |

demo 实例（:3210，含演示种子账号）是销售/演练面，**不冒充试用环境**。

## 3. 真实知识集

- 待天穹智能提供：其真实内部文档（建议 ≥1 库、覆盖多目录与多人协作场景），
  经 web 编辑与 git push 双入口入库。
- 仓库自带演示种子（product-notes/team-handbook 等）不冒充真实知识。

## 4. 执行步进（T4 展开即按此走）

1. 两环境部署（本地 compose 自验 + 托管环境部署，各留初始化演练记录）
2. 账号与角色落实（邀请流程走真实一次性令牌；Agent 走凭据创建→CLI setup）
3. 真实知识集入库（双入口；校验规则三端同一契约如实拦截）
4. 三角色 × 两环境走查（DOD-14 四子项：管理员/贡献者/Agent 使用面 + 两环境覆盖）
5. 反馈收集与分级处置（见 §5）
6. 复核记录：以 e1-closure-check 同格式追加，DOD-14 终判更新

## 5. 反馈分级处置（epic 规则 4 发布阻碍五类）

| 级别 | 类别 | 处置 |
|---|---|---|
| 发布阻碍 | 越权 / 凭据泄露 / 数据丢失 / 规则可绕过 / 备份不可恢复 | 修复后附重新验证证据方可关闭 DOD-14 |
| 一般 | 可用性/文案/体验 | 分类入册（tech-debt-tracker 或后续 epic），不阻塞 |
| 咨询 | 使用方法/边界澄清 | 答复并入文档（user/ 或 dev/ 手册） |

落入 backup-recovery 手册对应条目后 Q9 置 closed。
