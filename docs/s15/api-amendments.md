### A1 §13 表行更新（逐字可用建议文本）

**现状**：C3 建议稿的 /search 行只描述 q 关键词表单与结果表——无 vault 参数、无 ⌘K。

**建议**（以 C3 行文本为基线替换为以下文本；变化点：路由签名加 `&vault=`、下拉/直传/收窄/⌘K 四组语义句）：

```markdown
| GET /search[?q=][&vault=<slug>|all] | 元数据查找页（S5-T4；S15-T1 库筛选）：标题/标签/摘要关键词表单（maxlength=200）+ 库筛选下拉（GET 表单参数 `vault`，缺省 `all`=全部有权库；选项=「全部库」+当前员工有权库——与 GET /vaults 列表同一实时 JOIN vault_members 判定面，无权库绝不出现为选项——选项集与命中集同判定面）+ 结果表（库→browse、路径→view 链接；行含 库/路径/commit 三要素、标题、标签、摘要片段、命中字段标注；frontmatter 豁免文件如实标注无标题）；vault=<slug> 命中集收窄到该库（收窄在调用侧装配——查询面 LIKE 子串/可见性过滤/100 截断/确定性排序语义全保持）；直传 vault=<无权或不存在 slug> 按 D-IC-06「无权=不存在」处理——与未知库同形态（200 空命中+如实空态提示，不区分两种语义、零泄露——slug 不回显、不报「你无权」）；⌘K/Ctrl-K 聚焦搜索框（仅本页：页内增强脚本并入唯一内联 script 块；无 JS 时 GET 表单仍可提交——渐进增强）；与 §3.6 GET /api/v1/search 同一查询面同一鉴权判定面（实时成员关系，撤权下一渲染即消失）；结果超 100 行如实标注截断；空 q 表单空态、超长 q 422 同页提示；插值唯一通道 HTML 转义（XSS 诱饵不执行）；未认证 302 /login；GET 免 CSRF | S5-T4 / S15-T1 |
```

**理由**：

1. **筛选选项集是新侧信道面**（D26 延伸）：选项集与命中集必须同判定面。契约显式写明「无权库绝不出现为选项」与「直传按无权=不存在同形态」双语义，防止后续实现只过滤命中集而漏掉下拉选项（或直传时报「你无权」形成存在性 oracle）。测试锁定两侧（bob 下拉无 product-notes；直传与未知库逐字节同体）。
2. **状态筛选如实单态**（S15 D3）：v1 检索面只呈现已发布内容（search_index 派生自已发布分支），故不设独立 `status` 参数形态、不虚构多态筛选——该语义由行文「已发布」承载；工作台可见性声明由 S15-T2 落位。若未来出现草稿态检索需求，再议参数化。
3. **⌘K 属页面增强行为**（S15 D1：仅 /search 页内，不做全局快捷键）：以「渐进增强」措辞补记——零 JS 时 GET 表单仍可提交是验收面，契约锚点防回归。

**待裁决**：

(a) `vault` 参数落 §13 页面行文（本建议立场）还是升格 §3.6 API 端点参数（页面域先行——检索 API 消费方未提出该需求，不预设）；
(b) 直传「不区分两种语义」是否需要独立错误形态（当前与 D-IC-06 同页同体、无独立错误码——零泄露优先）；
(c) 与 C3/D13 的裁决顺序（两稿行文重叠——建议一并落契，本节文本为最终形态）。
