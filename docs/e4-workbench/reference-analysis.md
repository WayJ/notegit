## 1. 信息架构

应用壳 = 顶栏 ＋ 左侧分区导航 ＋ 右侧内容区。

- **顶栏**：品牌标记、品牌名、分隔线、工作区名、状态药丸、用户圆章。
- **侧栏**：分区标签（工作台）→ 导航项列表（图标＋文字，当前项高亮）→ 分隔线 →
  当前所在区（高亮）→ 底部用户卡（头像＋姓名＋身份）。
- **内容区**：最大宽 1220px 居中，页内自上而下九段式。

核心主张：**跨库聚合的工作台**。知识库是该工作台的一个区，不是独立产品孤岛——
导航里还有任务看板、数字员工、工作流、自动化、工件、用量六个同级区。

### 4.3 两条不可让步的红线

1. **聚合面是新的侧信道**。统计数字（可访问库数、文档总数）若与卡片不同源，
   无权库的存在性会被数字泄露——D-IC-06（无权=不存在同 404）在聚合面的延伸。
   统计与卡片必须走同一实时成员过滤面，且测试锁定。
2. **「维护者」列不是身份**。路径级文档行若用 git 提交者填充维护者，那是客户端可填
   的元数据（DOD-03），呈现必须如实标注来源，且**任何权限判定不得消费它**。
