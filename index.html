Git 为唯一真源的企业知识库

Notegit 供企业里的人和 AI 共同使用、共同维护：Markdown 与附件是知识内容，Git 是版本记录；已发布知识以库默认分支为准，管理数据不维护第二份权威副本。

快速开始 GitHub 仓库

员工本地 · 原生 Git

$ git clone https://notegit.example.internal/vaults/handbook.git
$ cd handbook
$ vim notes/onboarding.md
$ git commit -am "更新入职手册"
$ git push
# 服务端 pre-receive 统一校验
→ 校验通过，发布到默认分支 main

核心能力

安全内核自 v0.1 起成形，v0.2 收口内容生产与发现的表层。以下均为当前版本的实际能力，能力边界见「已知限制」文档。

Git 唯一真源

知识正文、附件与目录结构都活在 Git 仓库里，提交历史即版本记录；管理数据不维护第二份权威副本，标题、标签、搜索索引等派生数据均可从 Git 重建。

三入口一致授权

Web、Git HTTPS 与 ngt 命令行共用同一套库权限（阅读 / 编辑 / 管理）与员工身份；Agent 不另设权限体系，凭据只能收窄、不能扩大权限。

统一校验

提交前校验控制知识格式质量：服务端 pre-receive 对所有入口的推送统一执行（frontmatter、文档与附件大小、类型与库容量限制）；格式合规不等于事实正确。

历史与还原

每库保留完整提交历史，误删误改可从历史找回；第一版没有回收站与收藏，恢复即走 Git 历史。

全文检索

v0.2 起命中面覆盖标题、标签、摘要、文件名与正文，中文两字即可查询；检索结果按库权限逐请求过滤。

备份恢复演练

维护模式排空、数据库快照与 Git 复制抽样校验打包为一致备份（数据与密钥分置两件）；恢复流程经真实容器演练验证并留档。

三入口，同一套权限

浏览器、原生 Git 与命令行都落在同一套库成员权限（阅读 / 编辑 / 管理）上：撤权对三个入口同时生效，Agent 以员工身份操作。已下载到本地的克隆副本不自动收回，由企业设备管理承担。

Web

浏览器整理与查阅：目录浏览（README 渲染）、双栏预览编辑与草稿自动保存、站内新建笔记、最近变更流（v0.2）。

Git

原生 Git HTTPS 读写：clone / pull / push 零适配，Agent 与既有工具链直接可用；服务端 pre-receive 始终校验。

CLI（ngt）

本地工作副本管理：sync / ls 展示版本与同步时间，离线可读；断网时明示「可能过期」。

快速部署

单容器部署：Node 24 + Fastify + node:sqlite + git http-backend，数据落在一个持久卷。以下三条命令如实摘自 deploy/README.md：

deploy/README.md · 快速开始

# 构建（上下文 = 仓库根）
docker build -f deploy/Dockerfile -t notegit:0.1.0 .
# 运行（单实例 + 命名持久卷）
docker run -d --name notegit -p 127.0.0.1:3000:3000 -v notegit-data:/data notegit:0.1.0
# 或使用最小编排示例
docker compose -f deploy/docker-compose.yml up -d --build
  • 最低规格：1 vCPU / 768 MB 内存 / 2 GB 数据卷（推荐 2 vCPU / 1 GB / 20 GB）。
  • 对外建议保持回环发布 + 反向代理终结 TLS。
  • 首次初始化：起容器后用一次性管理员令牌完成 bootstrap。
