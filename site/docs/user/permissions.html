权限与撤权边界

Notegit 的权限模型一句话：库（Vault）是内容访问权限的最小单位，像 Git 项目一样按成员授权；网页、API、Git 三类入口共用同一判定，改一处三处同变。

库角色

角色读取 / clone / fetchpush管理成员与设置
reader（阅读者）允许禁止禁止
editor（编辑者）允许允许，受分支规则约束禁止
admin（库管理员）允许允许，受分支规则约束允许
  • 实例管理员是另一层：管部署、账号与全实例运维，不因此自动拥有业务库内容（新库默认私有，创建者为库管理员，不按库名推断权限）。
  • 库管理员经成员端点授权：PUT /api/v1/vaults/{slug}/members/{username}（角色 reader/editor/admin）；移除成员 = DELETE 同路径。
  • 需要隔离的内容拆库——库内没有文档级权限，status、owner、标签都不构成访问控制。

「无权」长什么样

对无权库，网页列表、搜索结果、Git 通道一律当作不存在（404），与「库不存在」同一表现——不泄露库的存在性。附件、历史、refs、对象同样不可访问。只读成员的任何写操作（网页提交、push）被 403 拒绝。

权限变更对后续服务端请求即时生效：移除成员后的下一次请求就不可见。

访问凭据（ngt_ 令牌）

Git 通道与 CLI 不用网页会话，用你名下的访问凭据：ngt_ 前缀令牌，在网页「我的凭据」页（/credentials，POST /api/v1/credentials）自助创建——name 与 expires_at 必填（有效期上限 90 天），明文仅创建时显示一次，此后界面只显示 ngt_ab…wxyz 形态掩码。

  • 令牌按 HMAC 摘要存储，服务端谁也拿不回明文；忘了就撤销旧的（DELETE /api/v1/credentials/{id}）再建新的。
  • 可选 scope 只能收窄权限（只读 / 限定部分库），不能扩大——给不同设备/Agent 发不同令牌是推荐做法，出问题时精确吊销。
  • 网页退出登录不撤销令牌（会话与令牌是两回事）；修改口令会使全部网页会话失效，令牌不自动撤销——需一并处理时页端有提示。

撤权后会发生什么

触发后续请求你本地已有的东西
成员被移除（撤权）该库网页/API/Git 一律 404；搜索结果下一查询消失本地克隆保留（见下）
令牌到期401（E-AUTH-002）换新令牌即可
令牌被撤销（自助或管理员代管）401（E-AUTH-003），即时生效同上
账号被停用全部会话与令牌 401（E-AUTH-004）联系实例管理员

两条硬边界：

  1. 已下载内容不能收回。撤权拦住的是后续请求；此前克隆到本地/托管工作副本、以及任何人已经读走的内容，由企业设备管理与保密制度承担。撤权后想收回终端副本，走设备管理渠道。
  2. 本地克隆不被自动删除。notegit sync 发现某库 fetch 收 404 时按撤权处理：跳过、在状态里标记 revoked、逐库报告，副本原样保留；确认不再需要时用 notegit sync clean 显式清理（遇未提交修改/未推送提交会先拒绝并给导出指引）。管理员重新授权后，下次 sync 自动恢复更新。

审计以认证主体为准

每次推送与网页提交，服务端记录的是认证身份（账号 + 凭据）、库、时间、旧新 commit 与结果。Git commit 的 author/committer 字段客户端可随意填写，不作为身份凭证——用谁的令牌推的，审计里就是谁。

给 Agent 使用者的推论

Agent 以你的员工身份工作：权限与你完全一致（凭据只能更窄），审计也记在你名下——发凭据给 Agent/Harness 时按最小范围收窄。详见 Agent 使用指南与已知限制。
