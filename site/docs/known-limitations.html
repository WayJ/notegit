已知限制（v0.1 · 2026-10-14）

Notegit 第一版（E1 范围）能力边界的集中声明，DOD-15 交付材料之一。三条来源逐条对齐：架构 §12 边界（设计决定，非缺陷）、第一版明确排除（roadmap 声明的范围外项）、本周期遗留（实现现状中尚未收口的具体项，附依据）。本文只声明现状，不承诺时间表；与架构 §12 的一致性由 cli/test/delivery-docs-consistency.test.ts 自动看守。

规则版本基线：1.0.0-draft.2（draft；rules-version.json）。

1. 架构边界（架构 §12，逐条）

这些是第一版的设计边界，按 §12 的处理方式运行：

边界现状说明
已下载内容不能收回撤权只拦后续请求（网页/API/Git 一致）；终端上的克隆副本与已读走内容由企业设备管理承担。本地副本不自动删除，notegit sync clean 显式清理且遇未导出数据先拒绝
库内没有文档级权限权限最小单位是库；需要隔离的内容拆库。status、owner、标签不构成访问控制
Agent 使用员工身份无独立 Agent 权限体系：操作权限与员工一致，凭据只能收窄；工具自报身份仅作线索，服务端审计记录真实认证主体
原生 Git 可跳过本地 hook服务端 pre-receive 始终校验（先写后删、合并提交、多 ref 推送同样拦）；格式合规不等于事实正确
本地副本可能不是最新ls/sync 展示版本与同步时间、断网明示「可能过期」；保留离线能力，不做强一致承诺
默认不强制审核不强制所有提交走 PR；需要约束时用 main_admin_only 限制默认分支写入。完整审核工作流属第二阶段
复杂文档与大附件第一版限制支持范围与容量（文档/附件大小、类型清单、单次 push、库容量、校验内存等限制键可配置），复杂格式按真实需求再扩展
Git 和数据库状态分离写入结果核对（审计 old→new 成链）、恢复对账 CLI、一致备份（维护模式 + 分置两件）覆盖；极端中断态经对账任务处置

2. 第一版明确排除（范围外，不是缺陷）

以下能力按 roadmap「第一版明确排除」声明不在 v0.1（详见 roadmap 与架构 §1.3/§12）：

  • 流程与身份：强制所有提交走 PR / 完整审核工作流（第二阶段）；SSO 与企业目录对接；文档级权限；独立 Agent 权限体系。
  • 内容与格式：富文本编辑器；Word/PDF/TXT 等复杂格式转换；正文全文/语义搜索（查找=标题/标签/摘要元数据检索）；AI 自动补全元数据；收藏、回收站（删除恢复靠 Git 历史）。
  • Git 侧：SSH 传输（第一版仅 HTTPS）；客户端写入 tag 及其他 ref 命名空间；Git LFS；跨库永久文档 ID（文档标识=库+路径，跨库移动历史不拼接，见历史边界）。
  • 平台与规模：通用 Git 项目平台功能（issue/CI/看板）；多实例/对象存储/高可用承诺（见「单实例假设」）；自动提交守护进程；MCP 与在线内容查询接口；Windows CLI（首发仅 macOS/Linux）。
  • 网页编辑：仅默认分支（候选修改经 Git 非默认分支）；拖拽目录排序（目录结构由 Git 路径表达）。
