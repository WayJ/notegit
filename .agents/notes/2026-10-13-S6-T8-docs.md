## 选型记录

1. **单 README 不拆 cli/docs/**：README 为 npm 包随包分发文件（package.json files 含 README.md），拆分会让发行包丢文档；五命令文档约 400 行在可维护范围，一致性测试也以单文件章节锚定更稳。
2. **帮助原文逐字内嵌而非改写**：抽检测试逐字包含断言是最强一致性形态（--help 即文档、文档即 --help）；改写式文档无法自动锁定。命令行为细节（错误表、修正流程）在帮助原文之外以 prose 补充。
3. **e2e 走 mock-server 而非真实服务实例**：与 T2 集成测试同选型（真实 git http-backend CGI + 模拟 /api/v1/credentials），lint 全程本地无服务端依赖，安装-login-clone-lint-fix-setup-commit 全链真实组件。
4. **ls 凭据面如实标注**：ls/lint 的凭据面仍是 NOTEGIT_SERVER/NOTEGIT_TOKEN 环境变量（credential-source.ts 现状），login 的凭据文件/helper 服务于 git 推拉、尚未被 ls 接管——README 在 ls 节与环境变量表明确标注此边界，不虚构「login 后 ls 免配置」。
