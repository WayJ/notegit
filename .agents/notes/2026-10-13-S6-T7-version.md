## 选型记录（brief 要求的两处 + 依赖面）

1. **server 读值方式 = 运行时读**（notegit-validation rulesManifest()，与 pre-receive 同机制同源）：构建期内联会引入第二份拷贝，漂移面更大，与 §7.3.1「构建/发布时从同一 git 路径取定义」的运行时权威（§5.4）相悖。
2. **CLI 打包 = dist 复制（vendoring）而非 bundle**：notegit-validation 未发布 registry（bundleDependencies 打进的是 .ts 源包——Node 拒绝对 node_modules 下 .ts 剥离类型，T1 实测缺陷形态）；引入 esbuild 等打包器违背 CLI 零构建依赖现状。vendored 落位 dist/node_modules/ 使 Node 解析器自然命中（不改写 import 说明符）；contract.ts 的 `../../../docs/contracts/` 相对定位恰指向 dist/docs/contracts/（构建期从唯一机器来源复制——不是第二份维护拷贝，一致性由构建断言锁定）。
3. **依赖面**：notegit-validation 移 dependencies → devDependencies（构建输入语义：构建期编译进 dist；发布产物自包含），yaml@2.9.1 转正 dependencies（vendored 副本运行时消费，安装态经 registry 正常解析，不复制第三方代码进产物）。pack.test D5 接线断言随之更新（devDeps 接线 + yaml + 双面无服务端私有依赖）。**package-lock.json +3/-1 行**为 cli/package.json 依赖面变化的机械同步（product gate 的 npm ci 要求 lock 同步）——不在 Ownership 列表内，属构建与打包接线的必然伴随改动，特此记录。
