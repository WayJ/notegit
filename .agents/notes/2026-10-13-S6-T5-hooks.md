## interface（T4/T6 对齐点；冲突点=无共享文件，main.ts/commands.ts 未动）
- `cli/src/hooks/staged.ts`（S6-T5 临时载体，等价 lint --staged 的核心）：
  - `scanStaged(cwd?) → { files: FileInput[], treePaths: string[], knownPaths: string[] }` —— 读 index 不读工作目录：`ls-files --stage -z` + `cat-file blob`；变更集 = index 相对 HEAD（mode 或 oid 变化均算；无 HEAD 根提交 = 全集；删除不进变更，§2.5）；treePaths = knownPaths = 候选提交（index）全 tree。
  - `lintStaged(cwd?) → { report: Report, exitCode: 0|1|2 }` —— `validate({ scope:'pre-commit', files, treePaths, knownPaths })`（packages/validation 单一来源，sprint D5）；扫描失败 → E-RUN-002 error 报告（永不抛出）。
  - **T4 对齐**：`notegit lint --staged` 应消费同一实现（或保持等价）；等价断言模板 = test/hooks-lint.test.ts 两条 deepEqual（hook --json 子进程 vs 进程内 lintStaged），T4 合并后建议换成为对真命令输出的断言。
- `cli/src/hooks/pre-commit.ts` —— hook 本体（随 dist 分发）：`node pre-commit.js [--json]`；缺省人读报告（文件+错误码+消息+阻断提示）、--json 输出 validation-report JSON；退出码 = 报告退出码（0 放行 / 1 校验错误阻断 / 2 运行错误 fail-closed 阻断）。
- `cli/src/hooks/install.ts` —— 最小安装面原语（T6 setup 组合）：`hookScriptSource({interpreter, hookTarget})` 生成 #!/bin/sh launcher（仅一处 exec、两个绝对路径、无相对路径/$PWD 推导）；`installHook({cwd, interpreter?, hookTarget?})`（自有→原地替换、外来→拒绝且不动原文件、缺 hooks 目录创建、经 `rev-parse --git-path hooks` 尊重 core.hooksPath、cwd 可为仓库内任意目录）；`isNotegitHook()`/`HOOK_MARKER` 重装识别。卸载还原与外来 hook 兼容链/明确报告两模式属 T6。

## decisions
1. hook 不经 `notegit <子命令>` 分发，由 launcher 直接 `exec <绝对 node> <绝对 dist hook>`（安装时固化）——避免与 T4 在 main.ts/commands.ts 相交，且运行不依赖 PATH 解析。
2. 不执行库内脚本是结构性保证：hook 进程只 spawn git plumbing（rev-parse/ls-files/ls-tree/cat-file）+ 调 notegit-validation；不 exec/source 库内任何文件。沙箱测试以 marker 文件断言（样本：仓库根 pre-commit、.githooks/pre-commit、scripts/setup-hooks.sh、evil.sh、package.json 生命周期脚本；已暂存与未暂存两形态）。
3. 已暂存的恶意样本按**数据**过校验（.sh 命中 E-LIMIT-002 清单外类型被拒）——内容进规则、不进执行。
4. knownPaths/treePaths 同候选全 tree（与 server publish pipeline 的 candidate.candidateTreePaths 同语义：链接存在性按提交后状态判定；E-PATH-004 含存量基线）。
5. fail-closed：运行错误退出 2 阻断（validation §6.1）；unmerged 条目不加守卫——git 提交前自拒未合并条目，hook 实际不会遇到。
6. 双 tarball 安装态（T1 移交）下 dist hook 经 node_modules/notegit-validation（exports=.ts，Node ≥22.6 类型剥离）加载——真实现装态冒烟留 T6/T7（与 T1 记录的分发形态裁定衔接）。

## evidence（2026-10-13，Node v24.21.0 / git 2.50.1 Apple Git / macOS 15）
- **npm test（monorepo）**：395（server）+ 106（validation）+ 105（cli = 80 基线 + 25 新增）= 606 全绿，exit 0。
- **gates**：contracts / tests / storage 各 exit 0；product（npm ci --no-audit --no-fund && npm test）全绿。
- **沙箱断言**：恶意样本两形态（已暂存/未暂存）均未执行（marker 文件全缺）；无效内容 `git commit` 被阻（无 HEAD 产生、输出含 E-FM-001 与恶意 .sh 的 E-LIMIT-002）；有效内容（含 W-FM-101 warning、正文引用恶意脚本的合法文档）放行且 marker 仍全缺。
- **hook≡lint**：hook --json 子进程报告与进程内 lintStaged() deepEqual（失败态 + 通过态/子目录运行）。
- **阻断语义**：hook 直跑退出码 1（校验错误）/0（无暂存内容）/2（非 git 仓库，E-RUN-002）。
- **分发**：dist/src/hooks/{git,staged,pre-commit,install}.js 随 npm pack 产物分发（pack.test dist/ 白名单已覆盖）。
