# S4-T4 Upload — 上传与附件

## background
breakdown §2.3 S4-T4 行：Markdown/图片上传受扩展名清单与容量限制、附件读取一律经鉴权、附件响应不绕库权限。T2 已留 view/attachments.ts 接口占位（预览页相对图片引用→鉴权通道 URL）；T3 已定形 submit 面（edit/submit.ts：单文件 upsert 走 publishWebSubmit，错误全部取自组件 validation 阶段报告）。基线 487+106 全绿。

## decisions
- **上传语义按 T3 定形的形状**：POST /vaults/{slug}/upload/{path}（application/octet-stream 原始字节，唯一契约类型）→ publishWebSubmit 单文件 upsert；附件与引用它的 Markdown 变更**分步提交**（先传附件得 URL，再经 T3 表单提交引用它的 Markdown——两个各自完整的发布链）。不设第二套校验（D7）：svg 拒（E-LIMIT-002）/超限（E-LIMIT-003）/.md 缺 frontmatter（E-FM-001）全部来自组件 validation 阶段，端点只做错误映射（422；error 携带 limit/limitKey/expected/actual 定位字段，issues 保留原报告 error 项）。
- **URL 不可枚举——选型：按 blob 寻址**。/vaults/{slug}/attach/{oid}[/{name}]，oid=40 hex Git blob OID（内容散列，不可猜测；无列表面）。被拒：路径直出（可枚举）、DB 随机 token 映射（引库外状态、与 Git 双源漂移）。鉴权仍逐请求 authorize read（无权=404 反存在性同页——持有效 URL 也不例外）；不可枚举与鉴权互补而非互替。附带语义：附件内容更新则旧 OID URL 失效，预览页每请求重解析（数据页实时渲染约定）。
- **同步接口两遍法**：T2 的 AttachmentImageUrlResolver 是同步接口，而 blob 寻址需异步读树（execGit 全异步——N4 教训，不引入 sync spawn）。预览渲染两遍：第一遍记录解析器收集相对图片引用（无引用即终态），按文档目录语义（repoPathOfRef：./、../、/ 仓库根绝对；越界/空段/畸形→null）解析仓库路径并读默认分支 HEAD 条目，第二遍查表解析器正式渲染（渲染管纯函数）。缺库/越界引用保留占位标注（不泄露树内容）。
- **传输护栏**：上传 bodyLimit=max(组装时生效 maxAttachmentBytes, 64 MiB) 只升不降（同 githttp bodyGuardCeiling 裁决形态）——护栏永不先于热生效 E-LIMIT-003 给费解 413；正式判定逐请求走组件（limits 覆盖链热生效，测试以 app_settings 加 .svg 键验证）。
- **svg 纵深防御**：内容类型按文件名段仅升格已知安全类型（png/jpg/jpeg/gif/webp/pdf/md）；svg 一律 octet-stream+nosniff——纵使管理员把 .svg 加进清单（清单制可配）也不以 image/svg+xml 出面（内嵌脚本属执行面）。附件响应恒 nosniff + private,no-store（库内容不落共享缓存，撤权无残留副本面）。
- **拒绝→HTTP 映射**（T7 整合前的最小语义）：validation 422；authorization/branch-rules/execution-point 403；base-commit 409（CAS 并发冲突不静默覆盖）；其余 500 fail-closed。无权/不存在/畸形路径 404 同页（D-IC-06）。会话 POST 受 CSRF 同源校验（app 级钩子自然覆盖）。

## lessons
- gitOut（测试夹具）面向文本：二进制断言走 blob OID 等价（sha1("blob <len>\0"+bytes)）或 rawPayload；execGit 面向 utf8 string，附件字节读取在 upload 模块自带 buffer 版 spawn（超时/SIGKILL 语义同源）。
- bash heredoc 传中文给 python stdin 会碰编码墙：UTF-8 内容经文件中转（Write 工具）再拼接。

## handover
- 维护模式 gate 未接：WebRoutesOptions 无 gate 缝（D5 不改既有行），上传/编辑 POST 的统一接线（含 maintenanceGate 注入与草稿/冲突 UX）属 S4-T7——pipeline 已留 maintenanceGate 参数。
- 预览直开图片文件（attachmentImagePage）仍为标注页；把 attach URL 用于该页展示（及上传 UI 页）留给 T7/T8 整合。
- multipart 表单上传未引入（无依赖、无 UI 需求）：fetch/XHR 直发 octet-stream 即契约形态；如需浏览器原生表单再议（新依赖需 ADR）。
