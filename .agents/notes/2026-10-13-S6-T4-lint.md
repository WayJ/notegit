## 关键决策与依据

1. **校验输入 = index 对象字节，非工作目录**：部分暂存场景（S1）由此构造「将提交的内容」；staged good + worktree bad → 通过（e2e 固化）。符号链接/gitlink mode 不读 blob（无本地对象/由 E-PATH-002/003 判定链首拦截，空 content 安全短路）。
2. **报告 scope=pre-commit**（validation §1 三端一致表）；报告形状/错误码/消息模板全部来自 notegit-validation（D5 唯一规则源——validate() + renderMessage/issueOf，零本地复制）。schema 断言复用 validation 包内嵌校验器（test/helpers/schema-check.ts 只读消费，契约示例同款自证）。
3. **N-UPGRADE-001 语义**：仅本地旧于服务端（SemVer -1）时附 `report.notices[]`（注册表模板单源渲染）；info 级、不改变退出码（§6：版本差异不构成拒绝理由）。校验 error 时跳过探测。
4. **退出码矩阵**：0=pass（可含 warning）、1=fail、2=用法错误（缺/双模式、未知旗标、位置参数——stderr 提示不输出报告）与运行错误（E-RUN-002 报告）。与 exit-codes.ts、validation §6.1 对齐。
5. **hook 等价入口**：`lintOnce(opts, deps?)` 返回 {report, exitCode, hint}，deps 全可注入（cwd/env/execGit/fetch/stdout/stderr）；等价性测试断言 lintOnce 报告 deepEqual CLI --staged --json 输出。
6. **路径非致命 UTF-8 解码**（替换字符）：深度字节核验不在第一版（契约 §5.2 同款口径）；NFD 路径按原样入判定 → E-PATH-001 正确拦截（macOS 常态）。
7. 开发态 workspace 依赖打通实证：dist JS 经 node_modules 符号链接 import notegit-validation 的 .ts 导出在真实路径剥离下可跑（T1 note「移交 T4」疑虑在开发态不成立；安装态内嵌打包仍属 T7）。
