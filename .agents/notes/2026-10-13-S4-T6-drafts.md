# S4-T6 私有草稿与保存/提交区分

## background
breakdown §2.3 S4-T6 行；T3 已定草稿 PUT 形状（edit/draft.ts 占位）；storage-model §3.7 @schema drafts 契约先行（S1-T5）——D11 模式：落迁移 0008 + 防漂移（migration-0006 同款逐行等价断言）。基线 527+106（rebase 到 sprint/S4 @ 314313e ⊇ T5）。

## decisions
- **草稿域落 `server/src/drafts/`（api 域而非 web/）**：§7 端点在 /api/v1 下，认证走 app.ts 统一缝（四状态 401 JSON 映射——web 页面守卫的 302 形态不适配 API 消费方）；组装点 app.ts append 一行注册（vaultsPlugin 同款缝，授权范围内最小越界——D5 单点规则针对 web/ 主链路）。
- **「清理或标已提交」取标记路径**：`status='committed'` + `committed_at`，行保留可追溯；**现行草稿 = active 行**——列表/单读/删除只作用 active（已提交不再可恢复：「私有草稿可恢复」指恢复未发布草稿，GET 无行=404）；同路径再 PUT 重置 active（UNIQUE(vault,author,path) + upsert 覆盖旧稿，created_at 不动）。
- **状态流转挂点 = submitEditForm（T3 submit 面）published 分支**：仅提交者本人草稿（作者私有——他人草稿不受影响，留待其 base 过时的 T7 冲突面）；标记失败不回滚发布也不虚假报错（发布事实以组件为准；尾差可由再保存/幂等 no-op 收敛）。拒绝（任何阶段）不动草稿——S3-T7 DraftPreserved「不发布、保留草稿」的存储侧对应。
- **PUT 校验面（提前反馈）**：路径形状（validatePathShape → E-PATH-001）+ content 按 maxDocumentBytes（E-LIMIT-001——checkFileLimits 的 knowledge 判定复用，storage-model §7「大字段超长控制」）；422 = T2 报告（scope=web-submit，api.md §2.3 非信封）；**frontmatter 不校验**（草稿允许不完整——完整校验属提交链单一来源 D7）。limits 热配置逐请求读取。
- **base_commit 列 NOT NULL**：空库 null 以 `''` 哨兵存储、读出还原 null（存储层映射，service 头注）。
- **JSON 传输护栏**：插件作用域覆盖 application/json 解析器 bodyLimit = max(maxDocumentBytes×6, 8 MiB) 只升不降（upload 同款裁决——Fastify 缺省 1 MiB 会先于热生效 E-LIMIT-001 给出费解 413/400）。
- **既有迁移测试 [1..7] 全等断言改派生**（allVersions()：从 1 连续递增即合法）——任务约束「断言禁全等硬编码版本表」+ S2 D6 教训；此后 append 迁移免改这 5 个文件（auth/credentials/0006/0007/vaults）。

## lessons
- `../` 路径段会被路由层归一化，到不了校验面——路径非法断言改用 `%5C` 反斜杠段（到达 handler 后 E-PATH-001 拒）。
- base-commit 阶段拒绝要求 base 是**库内真实提交**（candidate 阶段先拒库外 OID）——冲突用例须先推进分支再以过时基线重提（编辑器打开后他人先提交的真实时序）。
- drafts 表无专用索引（契约 §3.7 无 CREATE INDEX 行）——按 (vault_id, employee_id) 的查询走 UNIQUE 约束索引前缀；列表规模 = 单人草稿数，无需额外索引（契约只读纪律，不自行加）。
- 员工隔离的「同路径各自成稿」由 UNIQUE 三列复合直接保证（同库同路径不同作者不冲突）——测试互不污染的前提是每个用例自选路径。

## handover
- **T7 接线 POST /submissions 时走 submitEditForm 即自动获得草稿流转**（挂点已落在本任务）；edit 页 submit 按钮仍指向 /submissions（T7 前如实 404）；维护缝无需动作（app 级 maintenanceGuard 自动覆盖 /api/v1 非安全方法——gate.ts 注记明列「草稿」；CSRF 同理由 app 级 csrfGuard 覆盖）。
- **编辑页未做「打开时回填本人现行草稿」**：恢复面 = §7 GET 端点（API 级可恢复已测）；页面级回填建议随 T7 冲突提示（「刷新基线」流程）一并考虑——回填时须同时呈现 base_commit 旧值。
- api.md 已按 D12 渠道补录两处（任务授权）：§7 状态流转段 + §13 edit 行 stale 文案更新；storage-model 未动（@schema 块本就含 drafts，零漂移）。
- 他人 push/git 侧推进分支不触发草稿流转（提交者身份≠commit author，identity §8）——过时草稿由 T7 base-commit 冲突面呈现，属设计而非遗漏。
