## lessons

- **Orca worktree 基点陷阱**：worktree 克隆自远端 origin/main（旧基点），不含本地未推分支——首轮即要求 worker `git remote add local … && git rebase local/<sprint 分支>` 对齐；后续 sprint 的 spec 模板已固化该步骤。
- **worker_done 缺 taskId 会被运行时拒绝**（T1 首发即中招，补发成功）——协议自纠错有效，spec 中提醒双 ID 齐全。
- **并行契约任务的门禁交叉**：T5 的 api lint 断言「与 T2 前缀不相交 + rulesVersion 同源」，机器防撞比口头约定可靠，值得在 S3（packages/validation 落地）沿用。
- **验收前收口独立核对（T8 模式）价值显著**：抓出 8 项缺口（含 1 项场景字面不满足），避免了带病过闸。
- 用户接管终端（user_takeover）会阻止 worker-release 清理：改走 `worktree rm`；结算顺序应为 先验证集成 → 再 release → 再 rm worktree。
