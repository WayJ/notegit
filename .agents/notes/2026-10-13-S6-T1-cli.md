## 关键发现与决策（构建产物管线）
1. **Node 拒绝对 node_modules 下的 .ts 做类型剥离**（`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`）：首版 bin 直指 `bin/notegit.ts` 在 workspace 内可跑，但干净环境 `npm install -g` 后必炸（macOS 实测复现）。修复 = 分发产物走 `dist/` 纯 JS（tsc emit + 扩展名重写），bin 指产物。与 D5/T7 既有的「构建产物」口径一致（T7 构建断言的对象即 dist）。
2. **副产物收益**：dist 为纯 JS，产物层面 Node ≥22.13 声明真实成立；类型剥离只用于开发树（repo 开发环境 Node 24，无影响）。
3. **分发形态**：notegit-validation 未发布 registry 且 `exports` 指 `.ts` 源码（node_modules 内同样不可剥离）——本任务验收采用**双 tarball 安装**（`npm install -g notegit-0.0.0.tgz notegit-validation-0.0.0.tgz`，npm Arborist 以本地 tarball 满足依赖边）。
4. **移交 T4/T7（重要）**：T4 真正消费 validation 时，安装态从 node_modules 加载 `.ts` 导出同样被 Node 拒绝——需要 master 裁决 validation 的分发形态（随 CLI 打包 bundle / validation 出 dist / 多包发布）。packages/validation 本 sprint 对 S6 只读，本任务未动。
