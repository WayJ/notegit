## decisions

- **查询面 = SQL LIKE 子串，不做全文引擎**（breakdown 第 1 点选型义务）：`%`/`_`/`\` 一律字面化（ESCAPE '\'），ASCII 大小写不敏感（SQLite 内建语义）、其他文字精确子串；tags 匹配两段式——SQL 按 JSON 文本粗筛 + 应用层**逐标签**精确认证（跨标签 JSON 边界的子串不算命中），无认证候选行整行丢弃（粗筛只放大候选集，不产生假阳性）。升级路径 FTS5（T5 重建入口同源）。选型记录落 search-index-amendments.md「查找匹配选型」节。
- **鉴权过滤与授权层同一无缓存原则（D7/identity §5.1 第 2 层）**：过滤不在索引器（不烘进行、不快照），在查询 SQL 内实时 `JOIN vault_members`（与 listVaults/authorize 同一张表）；撤权 = DELETE 成员行，下一查询（API/页面同一面）即消失——无任何跨请求状态。token scope 清单非空时取交集（identity §3.4，与 GET /api/v1/vaults 同一收窄面）。
- **两入口同面**：API `GET /api/v1/search?q=`（search/routes.ts，任意认证员工；400 缺/空 q、422 超 200 字符、401 §1 通用）与页面 `GET /search?q=`（web/search/ 新模块，S4 骨架 append 一行注册；空 q 表单空态 200、超长 q 422 同页提示）消费同一 `searchKeyword()`（search/query.ts）——同一判定面由 e2e 页面/API 同集断言保证。
- **结果形状**：`{vault_slug, vault_name, path, commit_oid, title, tags, summary, matched}`——库/路径/commit 三要素（S5-T6 引用规范同形）+ 摘要片段（T3 已截 500 字符）+ 命中字段；title=null = frontmatter 豁免文件（README 等，如实记录不伪造）。确定性排序 vault slug → path；上限 100 行 + `truncated` 如实标注（不承诺分页）。
