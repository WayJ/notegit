## 关键决策与依据
1. **本地状态枚举 = not_cloned | cloned | behind | unknown**（比任务文本三态多显式 not_cloned——unknown 保留给「无法判定」；本地领先/分叉 fold 进 unknown，精确六态机属 S7 sync，架构 §7.3）。**已 ask 协调人裁定（msg_2a129b266b50），两个 600s 窗口未回**——按上述提案落地并固化进测试；若裁定不同，改点集中在 ls-unit 2 例 + ls.test e2e 2 相位断言 + STATUS_LABEL。
2. **远端 tip 经 `git fetch <cloneUrl> <branch>` + FETCH_HEAD**（任务原文允许「ls-remote 或 API」；fetch 为 ls-remote 超集——带回对象使 merge-base 祖先判定可行，纯 ls-remote 拿不到对象时 behind 不可判定。fetch 只写 FETCH_HEAD/对象，不动分支与工作区）。凭据走 git credential helper 配置（T2 面），token 不进 URL/argv。
3. **open（缺口记录）**：api.md 无远端 tip 端点——每库一次 git fetch 取 tip（N 库 = N 网络往返 + 对象下载）。服务端若提供 default-branch tip（如并入 GET /api/v1/vaults 响应），ls 可免 fetch 直拍字符串比较（精确 behind 仍需对象）。留待后续 sprint/master 裁定。
4. **测试自死锁教训**：测试进程内起假 API 服务器 + spawnSync 打 dist 子进程 = 父进程事件循环冻结 → 子进程 fetch 永等响应（双向死锁，--test-timeout 因同步阻塞失效）。修复 = 异步 spawn + await 收割。已写入测试文件头注释，T2/T4 测试同形态时直接复用该模式。
5. 本地根目录：默认 ~/knowbase（架构 §7.2），NOTEGIT_LOCAL_ROOT 覆盖；usage 冻结 `notegit ls [--json]`（不加旗标，防超任务面）。
