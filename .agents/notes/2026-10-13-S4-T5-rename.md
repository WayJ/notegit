# S4-T5 重命名与删除 + 维护闸门 web 缝

## background
breakdown §2.3 S4-T5 行 + T4 遗留移交（维护闸门 web 缝，master 指派随本任务）：重命名按**目标路径**重新判定（改 .md 须合法 frontmatter、改名 README.md 豁免——validation §2.5 第 5 点）、删除不做元数据校验但历史保留；基线 506+106 全绿（rebase 到 local/sprint/S4 @ 8d2bcf2 ⊇ 9157589）。

## decisions
- **重命名 = upsert(新)+delete(旧) 单变更集走 publishWebSubmit**：判定全部来自组件 validation 阶段（sprint D7 单一来源，本模块零第二套校验）——目标路径重判定**自然涌现**：changedFiles 以新路径进校验器（txt→.md 即 E-FM-001；raw 内容改名 docs/README.md 即豁免通过；README→普通 .md 不再豁免反向同判）。目标已存在 409 拒绝不覆盖（重命名不是覆盖写入）；同路径无操作 400。
- **删除 = 单条 delete 变更**：不做元数据校验（validation §2.5）——删除无 frontmatter 的 README.md/raw.txt 均通过（对照样本断言）；Git 历史不动（测试直查 `git show <seed>:path` 旧版本逐字保留——S5 历史页数据基础）；候选构造要求删除路径在基线 tree（路由先 requireSourceEntry 确认存在，目录 302 browse 不做目录级删除——最小可用面）。
- **维护缝（T4 遗留清偿）**：`WebRoutesOptions.maintenanceGate?` 注入（web/routes.ts）+ 组装点 `webWriteGuard` onRequest 钩子——凡 `/vaults/` 下**非安全方法**一律 503（backup §3 矩阵 web 行；未来 T7 edit submit POST 自动覆盖，无需再接线）。响应两路：octet-stream（程序化上传）JSON E-MAINT-001 + `details.maintenance` 标志；表单流程 503 HTML 同页提示。app.ts 装配处传 gate（一行——gate 实例生命周期在 buildApp 闭包内，装配点注入是缝生效的唯一通路，注记为对本任务边界的最小越界）。upload/rename/delete 的 publishWebSubmit 均传 `maintenanceGate`（组件 execution-point 最后一道——与 HTTP 层第一道双层同构，同 githttp「HTTP 403 → update hook」形态）。
- **表单 POST 形态**：`application/x-www-form-urlencoded` 原生表单（无 JS、无新依赖——模块内注册 parser 一次）；成功 302 PRG（改名→新路径预览页，删除→所在目录 browse）；拒绝同页回显（422 校验 E-FM 码+行 / 403 授权 / 409 冲突）；GET 表单/确认页 read 成员门槛（写权限提交时判定——edit 族同形态）。二进制安全：重命名读源走 buffer 版 cat-file（同 upload 形态，png 改名 blob OID 等价断言）。
- **目录页入口**：browse/pages.ts blob 条目 append `entry-ops` 链接（重命名/删除——GET 无写操作）；`includes` 断言的既有测试不受影响（data-* 属性原样保留）。
