## 兼容模式裁决（两模式都合法，选定并记录）
- **默认 = 模式 b「明确报告冲突拒绝安装」**（退出码 1，原文件一字节不动，指引 `--chain`）。依据：与 T5 install.ts 的保守立场一致（外来→拒绝且不动原文件），DOD-09「不破坏现有 hook」的最小惊奇路径。
- **`--chain` = 模式 a「兼容链」**：原 hook 原样（字节+权限，rename 保留）移至 `<hooks>/pre-commit.user`；launcher 先调用原 hook、通过后再 `exec` notegit 校验（「追加调用」语义：原 hook 改写/重新暂存内容时，notegit 校验的是最终将被提交的内容）。
- 顺序理由：若 notegit 校验在前且用户 hook 会重排内容，会在可自动修复的形态上提前阻断。
- **`-x` 守卫对齐 git 自身 hook 激活语义**：不可执行的原 hook 安装前 git 就不运行，保留后也保持休眠（不会被我们的直接调用「激活」）；卸载按字节+权限还原（测试含不可执行态）。
- DOD-09「不执行库内脚本」边界：launcher 只 exec ① `pre-commit.user`（.git/hooks 下用户本地配置，非知识库工作树内容；保留其执行=保留用户既有行为）② 随工具分发的 hook 本体（绝对路径）。绝不执行工作树内任何路径（T5 沙箱保证未动）。
- 冲突防护：`pre-commit.user` 已存在且当前 pre-commit 又是外来 hook → 拒绝（不覆盖此前的保留件），指引先 `--uninstall`。

## interface
- `cli/src/setup/hooks.ts`：
  - `installPreCommit(cwd, {chain?, interpreter?, hookTarget?}) → { exitCode, stdout[], stderr[] }` —— 无外来 hook 路径直接组合 T5 `installHook`；chain 路径自写 `chainScriptSource({interpreter, hookTarget, userHookPath})` launcher（含 HOOK_MARKER，重装/卸载识别同 T5）。退出码：0 成功/幂等重装、1 两类拒绝、2 运行错误（非 git 工作树等）。
  - `uninstallPreCommit(cwd)` —— ours+保留件 → rename 还原；ours → unlink；外来 → 不动（0）；孤立保留件（无 ours 但 .user 在）→ 只提示不自动还原（0）。幂等。
  - `USER_HOOK_NAME = 'pre-commit.user'`；hooks 目录解析与 T5 同语义（`rev-parse --git-path hooks` 尊重 core.hooksPath，cwd 可为仓库内任意目录）。
- `cli/src/setup/config.ts`：`cliConfigPath(env)`（NOTEGIT_CONFIG_FILE > XDG_CONFIG_HOME > HOME/.config；与凭据文件同族但分开存放——配置非机密、凭据是泄漏面扫描对象）、`readCliConfig`（k=v、坏行忽略、缺文件空）、`writeCliConfig`（合并保留未知键、0600、目录 0700 递归创建）。
- `cli/src/setup/index.ts`：`runSetup(args)` —— 参数解析 → hook 步骤 → `--local-root`（缺省取 env NOTEGIT_LOCAL_ROOT；`~` 按 HOME 展开后 resolve 持久化）→ 凭据检查（按已存凭据的 protocol+host 核对 `credential.<scope>.helper`，未登录/未注册/已注册三态，纯提示不阻断）。
- `cli/src/ls/local-status.ts` `localRootOf` 升三级：env NOTEGIT_LOCAL_ROOT > CLI 配置 localRoot > `~/knowbase`（消费 setup 持久化的根；ls 其余不动）。
- `cli/src/main.ts` 派发一行；`cli/src/commands.ts` setup 条目 `implemented: true` + usage/options/detail 同步。
