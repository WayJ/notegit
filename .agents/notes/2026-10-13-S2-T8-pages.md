## decisions

- **页面形态（brief Change 1/2）**：服务端渲染 GET 外壳（`server/src/web/`，4 页：/login、/、/admin、/credentials）+ 页内 vanilla fetch 调 api.md 既有端点（JSON、同源 Cookie、非安全方法浏览器自动带 Origin）。不引前端框架/路由/样式（YAGNI，架构 §6 完整 Web 整理属 S4）。动态数据一律 `textContent` 注入（无 innerHTML）；服务端插值唯一通道 `escapeHtml`。
- **页面安全不降级**：页面只是展示层——全部操作的安全判定在 API 侧（既有 authorize / 实例管理员门槛，零新增授权代码路径）；/admin 页面层另做 403 兜底（非实例管理员）与 302（未认证）；管理入口仅在 `/` 服务端渲染给 is_instance_admin（验收断言「普通成员看不到管理入口」）。
- **CSRF（brief Change 5）**：页面 fetch same-origin ↔ T5 守卫（Origin→Referer→reject）兼容验证落在 web-pages.test.ts（带 Origin 201/403 与缺源头 E-AUTH-006 各一）；页面路由全 GET（安全方法免校验）。
- **rehash-on-use 落地（S2-T4 留言「留 S2-T8」的欠账）**：token 域 `CredentialsService.authenticate`（retired 键命中即回写 active 哈希）+ 会话域 `auth/subject.ts`（多键查表 + sid_hash 回写；为此 `createRequestAuthenticator`/`registerAuth` 的 pepper 参数从 active 键改为整个 PepperFile）。K5 一次性令牌（邀请/重置/bootstrap）**不消费 retired 键**——active-only，轮换后未消费令牌立即失效（credentials-ops.md §3/§5 如实记录）；如需迁移期保活属后续运维任务决策。
- **consumePasswordReset 补会话失效（api.md §3.2 欠账）**：T2 注释「sessions 表落地后执行 DELETE」一直未落；本次补 `DELETE FROM sessions WHERE employee_id = ?`（重置完成 = 该账号全部会话失效；token 不自动撤销）。

## shape-diffs（页面消费 vs api.md 既有端点）

- **GET /api/v1/admin/employees（api.md §3.1 既有定义、此前未实现）**：本任务落地（管理页员工列表需要）；实现定稿——排序 `username` 升序、cursor = 上一页最后 username（api.md 未定排序与 cursor 编码）；`limit` 默认 50 上限 200（§1 通用约定）。
- **POST /api/v1/admin/employees/{username}/password-reset（api.md §3.1 既有定义、architecture-notes §8.7-3 挂账）**：本任务销账落地；审计主体 = 触发管理员（载体归因，§8.4 形态；detail 记 `{username, via: admin_triggered}`），消费端点（§3.2）主体仍 = 目标员工——两行同 kind `employee.password_reset` 不同主体。
- **维护模式无状态查询端点**（T7 只 POST/DELETE）：管理页不显示当前状态，仅提供开/关两钮（页面文案注明）。
- **api.md 无「全部库列表」端点**（GET /api/v1/vaults 仅本人成员关系）：管理页「成员与角色管理」列出**我任库管理员的库**（role==='admin' 过滤）——实例管理员非库管理员时管理其他库成员走库管理员自己操作（api.md §5 授权语义如此，未加实例级越权口子）。
- **PATCH /api/v1/admin/employees/{username} 必带 active**：实现将 active 设为必填（api.md 请求形 `{active, is_instance_admin?}`）；管理页「设为实例管理员」按钮因此同时回传当前 active。
